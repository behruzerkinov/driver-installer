## Phase 2: Devices

  - Reads hardware IDs, compatible IDs, description, manufacturer, class GUID.
  - Reads driver version and date from device registry key.
  - Gets problem code via `CM_Get_DevNode_Status`.
  - Derives device state (Ok, Missing, Outdated, Problem, Unsigned).
- Device list in `DeviceList.cpp`:
  - ListView wrapper with groups by class GUID.
  - Extended styles: checkboxes, double buffer, full row select, grid lines.
  - Columns: Device, Status, Installed version, Available version, Source.
  - Custom draw handler for status coloring (stub).
  - Virtual mode for >2000 devices.
  - Keyboard: F5 refresh, Ctrl+A select all, Delete clear selection.
- Details pane in `DetailsPane.cpp`:
  - Displays device description, manufacturer, instance ID, hardware IDs, compatible IDs, installed INF, installed version.
  - Candidate section (empty until ranking wired).
  - Install, Choose another candidate, Force install checkbox buttons.
  - Copyable fields via clipboard.
- MainWindow in `MainWindow.cpp`:
  - Header bar with search edit, theme toggle, settings button.
  - Toolbar with Scan, Install selected (N), Undo last batch buttons.
  - Split body with device list and details pane.
  - Status bar with pack root, driver count, last scan time, current task.
  - Minimum size 980x620.
  - Window geometry persistence via Settings.
  - DPI change handling via WM_DPICHANGED.
  - Theme application via DWM attributes and SetWindowTheme.

**Tested:**

**Known limits:**

## Phase 3: Packs

**What was built:**
- INF parser in `InfParser.cpp`:
  - Detects UTF-16 LE, UTF-16 BE, UTF-8, ANSI via BOM.
  - Parses `[Version]` section: `DriverVer`, `Class`, `ClassGuid`, `CatalogFile`, `Provider`.
  - Parses `[Strings]` section and resolves `%StringKey%` references.
  - Handles comments (`;`), empty lines, basic key=value.
  - Version and date extraction from `DriverVer`.
  - File size limit 16 MB, line length limit 8192 characters (documented; enforcement deferred).
- PackIndex in `PackIndex.cpp`:
  - Binary format with "DNIX" magic, version 1.
  - Header: magic, version, record count, root path (null-terminated UTF-8).
  - Records: hardware ID (length-prefixed UTF-8), INF relative path, packed version (uint64), date epoch (int64 FILETIME), file mtime (int64).
  - Load by reading file; Save by writing file.
  - Hash index: lowercase hardware ID → record indexes (unordered_multimap).
  - Lookup returns vector of record indexes.
  - Rebuild scans pack root for INF files and parses them.
  - Incremental update (simplified; falls back to full rebuild).
- PackScanner in `PackScanner.cpp`:
  - Recursive directory walk using `FindFirstFileExW` with `FIND_FIRST_EX_LARGE_FETCH`.
  - Finds `.inf` and `.cat` files.
  - Checks if a catalog exists next to an INF.
- Ranker in `Ranker.cpp`:
  - Implements scoring table from section 7.3.
  - Exact match primary: 1000.
  - Exact match other: 800 - 20 * index.
  - Compatible ID only: 400.
  - Class GUID bonus: +50 (deferred, needs class GUID in record).
  - Newer date: +30.
  - Newer version: +40.
  - Signature bonus: +100.
  - Unsigned penalty: -500.
  - Manufacturer bonus: +20 (deferred).
  - Problem device: +25.
  - Tie-break: newer date, newer version, shorter path.
  - Returns top candidate and up to two alternatives.
  - Filters unsigned when showUnsigned is false.

**Tested:**
- Unit tests written for INF parser, Ranker, PackIndex, Hash, Path validation.
- Tests compile conceptually; no actual run verification.

**Known limits:**
- INF parser model section parsing (manufacturer models with hardware IDs) not fully implemented.
- Ranker needs actual InfEntry data from parser to score correctly (currently uses record fields only).
- Signature check delegated to Verify but not integrated into ranking flow.
- Index incremental update simplified.

## Phase 4: Install

**What was built:**
- RestorePoint in `RestorePoint.cpp`:
  - Loads `srclient.dll` at runtime (not statically linked).
  - Calls `SRSetRestorePointW` with type `DEVICE_DRIVER_INSTALL` (10).
  - Returns handle for later close.
- Installer in `Installer.cpp`:
  - `InstallInf`: Runs `pnputil.exe /add-driver "<inf>" /install` via `CreateProcessW`.
  - Parses output for "Published name:" and success/failure.
  - `InstallBatch`: Creates restore point, installs each driver sequentially, verifies, returns results.
  - `RollbackInf`: Reinstalls previous INF via pnputil.
  - `CleanOldPackages`: Lists driver store packages (stub for user selection).
  - `ListDriverStore`: Enumerates third-party packages via `pnputil /enum-drivers`.
- Verify in `Verify.cpp`:
  - `VerifyCatalogSignature`: Uses `WinVerifyTrust` and `CryptCATAdmin` APIs.
  - `VerifyInstallation`: Checks INF in `%WINDIR%\INF`, checks catalog, verifies signature.
  - `GetCatalogSigner`: Returns signer name (stub).

**Tested:**
- Code compiles conceptually; no actual driver installation test.

**Known limits:**
- `CreateProcessW` pipe capture not fully implemented (stub uses a simplified approach that doesn't actually capture stdout).
- Restore point close not implemented (delegate to `SRSetRestorePointClose`).
- Rollback only reinstalls previous INF; full System Restore guidance is shown in UI.
- Clean old packages requires user explicit action; no automatic deletion.

## Phase 5: Online and Polish

**What was built:**
- Downloader in `Downloader.cpp`:
  - Uses WinHTTP with `WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`.
  - Sets `WINHTTP_OPTION_SECURE_PROTOCOLS` to TLS 1.2/1.3.
  - Downloads to `.part` file, renames on success.
  - Verifies SHA-256 via BCrypt after download.
  - Supports progress callback with current bytes, total bytes, speed.
  - Supports cancel via atomic flag.
  - Checks `Accept-Ranges` header for resume support (stub).
- Hash in `Hash.cpp`:
  - SHA-256 via BCrypt (`BCRYPT_SHA256_ALGORITHM`).
  - Computes hash of file or byte span.
  - Returns lowercase hex string.
- JSON manifest parser (hand-written in `Downloader.cpp`):
  - Parses `hardwareIds` array, `url`, `sha256`, `size`, `signer`.
  - No external JSON library (per spec).
- Settings dialog stub in `Dialogs.cpp`.
- About dialog in `Dialogs.cpp`:
  - Shows version, license, project URL (from CMake variable), copy diagnostics button.
  - Diagnostics string includes version, OS build, device count, index size, pack folders, online status, theme.

**Tested:**
- SHA-256 known vector test written.

**Known limits:**
- Online manifest download not wired to device scanning.
- Settings dialog is a stub message box.
- Download resume not implemented.
- No actual download test.
